# WiFi-CSI：我的探索与判断

中文 | [English](README.en.md)

**我想通过这个项目说明：Wi-Fi CSI 可以让我观察到运动引起的变化，但“看见波动”和“准确解释运动”之间，仍然有很大的距离。**

这是一个以 ESP32-S3 为接收端的技术学习项目。我的重点是实际尝试后的理解与判断，而不是展示一个已经成熟的检测产品，也不是继续深入复杂算法研究。

## 我的结论

经过这次测试，我认为这项技术有一定可行性，但影响结果的因素太多。运动的位置、接收器的朝向和动作本身都会改变看到的波动。仅凭当前输出，我无法判断某次变化究竟来自靠近发射源的运动，还是靠近接收器的运动，也无法把波动大小直接解释为动作大小。

**因此，我目前更看重它在条件明确的场景中，用于观察“是否发生运动或状态变化”的价值；对于详细、准确地同时判断位置、动作大小和多种物体特征，我仍持保留态度。** 这是我对这套装置的实测判断，不是对所有 CSI 方案能力上限的断言。

## 我怎样探索这个问题

我最初关心的并不是接收到了多少条数据，而是：大幅运动和小幅运动，到底能不能呈现不同的结果？还是最后都只表现为一次波动或一个 `ACTIVE` 状态？

项目从原来的“CSI 触发摄像头”路线拆出。摄像头移除后，我使用重新部署的独立 CSI 接收固件，在 10、20、30 秒的观察窗口中查看变化。实际操作中，我进一步改变了运动位置和接收器的朝向，并试了声音及现场外界噪声的影响。

| 我尝试的对照 | 我看到的现象 | 这让我想到什么 |
| --- | --- | --- |
| 靠近发射源端与靠近接收器端 | 靠近发射源端时，显示波动明显小于靠近接收器端时 | 同样在空间中发生运动，响应仍与位置有关；不能只凭波动强弱判断动作大小 |
| 接收器正面与反面 | 正面的响应明显超过反面 | 接收器的摆放和方向也是影响结果的条件 |
| 声音与现场外界噪声 | 在我测试的条件下，影响几乎不明显 | 本次声音尝试没有带来明显变化，但不能因此排除其他环境因素 |

这次探索让我把问题从“能否检测到运动”推进到“检测到变化之后，能否知道它是什么”。对我而言，后一件事才是当前方案的主要局限。

## 为什么我没有把它写成大小动作识别成功

九组采集中，我改变过位置或朝向。因此，动作、位置和方向的影响混在一起，这批数据不能作为固定条件下的大动作／小动作分类验证。

图中的 `stationary`、`small`、`large` 是当时页面的提示，而不是经过控制变量确认的真实类别。我保留曲线，是为了展示探索中实际出现的变化，不会根据某个峰值更大，就认定它对应更大的动作。

## 我想到的一个方向：主动振动下的损伤检测

我提到“损伤检测”，指的是让物体产生小幅振动，而不是看一个静止物体就判断它有没有损伤。

我的设想是：对物体施加可重复的小幅激励，观察不同部位的振动响应，尝试提取振动频率与幅度等特征，再与健康状态的基准比较。如果某个部位的响应发生异常变化，是否能由此获得损伤线索？

我认为这种对象和条件更明确的状态观察，是一个值得思考的应用方向。但它还是设想：当前实验没有完成振动幅度标定、不同部位分离或损伤验证。振动频率也不能直接换算为振幅，现有波动指标不能当作已测得的物体振幅。

## 我希望这个项目表达什么

我希望留下的是自己的学习过程：先搭起接收链路，再看真实数据，通过改变条件发现限制，最后形成对技术适用范围的判断。

对我来说，这个项目的成果是理解了“能接收到变化”与“能准确解释变化”的区别。暂时不把它扩展为复杂的多目标检测系统，也不把尚未验证的设想写成已经实现的能力。

## 实现与记录

链路为：**路由器发射回应 → 空间传播 → ESP32-S3 接收 CSI → 电脑记录与显示**。接收板会发出 Ping 促使路由器回应；“接收端”是其在观察框架中的角色，并不代表无线电完全不发射。

独立固件 `standalone-0.1.0` 已烧录并通过 10/20/30 秒接收检查，摄像头回包等待已解除。公开应用源码不包含本机完整依赖和私有配置，复现边界见固件说明。
